# 推理分析 → 优化实验 → 验证记录

三类报告共用白底、细分隔线和少量状态色，CSS/JS/SVG 全部内嵌，无 CDN、字体下载或联网依赖。`index.html` 串起过程；单独的推理与实验 HTML 也能直接打开。模板和前端资源随 wheel 分发。

## 1. 采集：得到真实时间线

已有 PyTorch Profiler / Chrome Trace 可直接使用。对于在**当前线程实际运行**的算子或完整 Block，可以使用可选接口：

```python
from vidinfer import RuntimeConfig
from vidinfer.reporting.capture import capture_profile

RuntimeConfig(workspace='/mnt/nas/vidinfer').configure()
# block/args 由调用者提供；先完成权重加载、编译和预热。
with capture_profile('/mnt/nas/vidinfer/profiles/block-test', label='model/block_00'):
    output = block(*args)
```

目录必须不存在，避免覆盖旧采集。输出 `trace.json` 与 `capture.json`。默认采集 CPU+CUDA，等待设备完成后导出；该同步与 profiler 自身都有开销，不能把采集耗时当作无 profiler 的基准。

不要仅在主线程把 `H3Session.submit()/wait()` 包进 profiler：模型实际运行在 Engine 工作线程，CPU 操作可能不在该采集线程内。本轮没有改动 Engine 的执行/资源生命周期；H3 完整推理继续复用已有的官方推理采集脚本，把其 trace 和 summary 导入以下命令。`cuda=False` 可以导出 CPU trace，但本轮 GPU 分析模板会拒绝没有 GPU 活动的 trace。

## 2. 分析：从 trace 生成推理报告

```bash
vidinfer analyze \
  --trace /mnt/nas/profiles/denoise_trace.json \
  --summary /mnt/nas/profiles/summary.json \
  --scope '第二次 DiT 前向；阶段数据来自同次完整推理' \
  --output /mnt/nas/reports/inference
```

`--summary` 可省略。支持旧采集脚本的 `phases/forwards`，或 Session 请求记录里的 `metadata.stages/forward_ms`。缺失阶段显示未采集，不推测数值。输出 `analysis.json`、`report.md`、`report.html`。普通电脑只需要核心包就能分析/渲染，不需要 Torch。

推理报告包含：

- 阶段 CPU Wall 与峰值 allocated，可隐藏权重/组件加载阶段的图表。
- GPU 热点总和、调用次数与启发式分类，可搜索 Kernel 名称。
- GPU 时间线，按已采集 GPU annotation 的 Block 切换，也可输入起止时间；点击活动查看完整名称。
- 逐次前向时间与 profiler 标记、CPU inclusive 热点、输入文件 SHA256、下一步实验建议。

只解析完成的 `ph='X'` GPU kernel/memcpy/memset 和 CPU op。GPU annotation 可定位 GPU 范围；不拿 CPU annotation 的结束点冒充 GPU 完成点。默认 HTML 时间线最多展示 10000 个活动，超过时按时间序列均匀抽样并提示；统计指标始终使用全部有效活动。

Kernel sum、GPU activity span、区间 union 是不同指标：多 Stream 重叠时 sum 可以超过 span。覆盖率不是 SM 利用率；Kernel 名称也不能证明 compute-bound 或 bandwidth-bound。硬件计数器分析仍需 Nsight Compute 等厂商工具。

## 3. 实验：复用统一算子协议

```bash
vidinfer experiment --config tools/experiments/attention.json --workspace /mnt/nas/vidinfer
vidinfer experiment --config tools/experiments/swiglu.json --workspace /mnt/nas/vidinfer
vidinfer experiment --config tools/experiments/qk_norm_rope.json --workspace /mnt/nas/vidinfer
```

新报告增加耗时/显存图表、Event/同步 Wall 切换、通过项过滤、误差明细和原始样本。未通过数值验收的路径不会因为速度快而被写成可采用的优化。`experiment` 的测量协议与 CUDA Kernel 未改变。

旧 JSON 可直接套用新版模板，无需重跑 GPU：

```bash
vidinfer report /mnt/nas/experiments/results.json --output /mnt/nas/reports/experiment
vidinfer report /mnt/nas/reports/inference/analysis.json --output /mnt/nas/reports/inference-view
```

## 4. 串联：构建研究总览与离线目录

先运行仓库内的**示例数据**，确认模板/安装环境。示例数字不是真实性能证据：

```bash
vidinfer workflow --manifest tools/reports/workflow-example.json --output /mnt/nas/reports/demo-01
```

再将清单中的输入改成自己的文件。路径相对于 manifest 所在目录解析；输出目录必须不存在：

```json
{
  "schema_version": 1,
  "title": "模型推理分析与优化",
  "note": "不同范围分开展示，不合成端到端加速比。",
  "inferences": [{
    "name": "第二次 DiT 前向",
    "trace": "capture/trace.json",
    "summary": "capture/summary.json",
    "scope": "一次前向",
    "note": "注明采集日期、模型与阶段范围。"
  }],
  "experiments": [{
    "name": "Attention 后端对比",
    "results": "experiment/results.json",
    "hypothesis": "针对热点验证布局与后端选择。"
  }],
  "evidence": [{
    "level": "完整 Block",
    "status": "historical",
    "file": "validation/block.json",
    "note": "历史证据；需核对是否适用于当前配置。"
  }, {
    "level": "完整去噪与生成质量",
    "status": "pending",
    "note": "单算子通过不能自动覆盖后续验证。"
  }]
}
```

总览生成 `index.html`、`inference-NN.html`、`optimization-NN.html`、`workflow.json` 与 `data/`。子报告可返回总览。直接复制或压缩整个目录即可离线查看；原始大 trace 不默认打包，保留来源文件指纹。

证据只复制 manifest 显式指定的 JSON/Markdown/文本文件，不读取报告内任意路径。`pass/fail/pending/historical` 是操作者声明，工具只验证文件存在并计算 SHA256，不自动认可质量结论，也不更改模型计划。

失败的 bundle 留下 `completed=false` 的 `workflow.json`；重新生成时请换新目录，避免与不完整记录混合。报告和原始数据可能包含私有路径与 prompt，未经脱敏不要公开上传。
