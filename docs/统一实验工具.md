# 统一实验与报告：第一课

目标是把之前各脚本重复的输入、误差、计时、显存与报告组织起来。本轮只做单算子，不加载模型、不自动替换模型执行计划。现有 Attention 与融合 Kernel 的数值实现保持不变。

## 从一条命令开始

在已安装本项目及 CUDA 依赖、CUDA 编译工具链的 Linux 环境运行。先从小输入确认环境，再换真实输入。容器必须把 workspace 放到 NAS。

```bash
vidinfer experiment --config tools/experiments/attention.json --workspace /mnt/nas/vidinfer
vidinfer experiment --config tools/experiments/swiglu.json --workspace /mnt/nas/vidinfer
vidinfer experiment --config tools/experiments/qk_norm_rope.json --workspace /mnt/nas/vidinfer
```

每次创建独立 `workspace/experiments/UTC时间-随机ID/`，包含 `results.json`、`report.md`、`report.html`。HTML 无需联网，可复制到另一台电脑打开。配置错误直接拒绝；设备/准备错误会留下 `completed=false` 的报告。GPU 不可用时不能跑算子，但可以在普通电脑重新渲染已有结果：

```bash
vidinfer report /path/to/results.json --output /path/to/view
```

核心安装不安装 Torch；指标计算需要 NumPy，实际实验还需要 README 的 CUDA 依赖。CLI help 和报告渲染不会导入 Torch。

## 第一层：ExperimentSpec，先写清实验问题

阅读 `src/vidinfer/experiments/spec.py`。dataclass 是一组有名字的配置字段；`__post_init__` 在对象建立后检查字段。我们强制候选名唯一、参考属于候选、容差合法，避免把配置错误留到大张量分配之后。

- `operation`：attention、swiglu 或 qk_norm_rope。
- `source`：合成输入种子及形状，或本地 Tensor 文件。
- `reference/candidates`：参考与待测实现。Attention 强制单一 SDPA 后端，不允许静默 fallback。
- `mode`：exact 检查有限值的位模式（含正负零）；allclose 检查每个元素 `abs(got-ref) <= atol + rtol*abs(ref)`。
- `cycles`：均衡顺序重复次数。N 个可运行实现，每周期执行 N 个旋转顺序及其反向，每实现得到 `2*N*cycles` 个样本。

## 第二层：cases，把一次调用的边界统一

阅读 `cases.py`。每个实现都是一个零参数函数，闭包持有同一份输入，统一返回具名 Tensor 字典。函数内部发生的所有工作计时；文件读取、H2D 和输入构造发生在函数外。

- Attention：输入/输出统一 BLHD、BF16、无 mask/causal/dropout。view 路径复用 `NativeStrideAttention`；contiguous 路径在函数内转换为 BHLD。两者都在函数内返回连续 BLHD 输出。
- SwiGLU：输入 packed `[a,gate]`，输出 `a*SiLU(gate)`；不包含 Linear 投影。
- QK：输入 Q/K、RMSNorm 权重与 cos/sin，输出 Q/K 两个 Tensor；参考复用 Diffusers 的 RoPE，CUDA 路径复用原 Kernel。保持 BF16 舍入、D128、partial half-split RoPE96；不包含 QKV 投影或 Attention。

### 复用真实输入

Attention 文件直接兼容历史 `real_qkv.pt`：字典键 `query/key/value`，值为 CPU BF16 BLHD Tensor。配置的 `source` 改为：

```json
{"kind": "tensor_file", "path": "/mnt/nas/captures/real_qkv.pt"}
```

相对路径按配置文件所在目录解析。加载使用 `weights_only=True`；记录整个文件 SHA256，保留文件中的 stride。不要把私有捕获文件提交到 GitHub，也不要把 stride 整理提前到计时外。

另外两种算子也支持 Tensor 文件：SwiGLU 键 `packed`；QK 键 `q/k/weight_q/weight_k/cos/sin`，可带标量 `eps_q/eps_k`。可选 `metadata` 必须可 JSON 序列化，用于标注模型版本、层、时间步与捕获位置。用户提供的 metadata 是来源声明，不等于框架已验证该来源；需要额外的捕获清单/哈希证据。

## 第三层：runner，验证和计量必须分开

阅读 `runner.py`，按以下顺序理解：

1. 显式配置缓存目录、读取配置、记录环境和源码指纹。
2. 在本进程独立 Stream 准备同一份输入。
3. 首次调用单独记录，包含懒初始化/编译。基准不可用时整轮停止，不更换基准。
4. 比较输出；大 Tensor 分块拷回检查。布局/shape/dtype/device 也属于协议。
5. 预热；均衡顺序测 CUDA Event 和等待完成的 CPU Wall。输出至少保留到 Event 完成。
6. 另做一次稳态显存测量，扣除输入及既有缓存的 allocated 基线。
7. 输出报告；出现 CUDA 同步故障时停止，不继续输出一张看似有效的性能表。

`probe_error` 表示调用或输出协议报错，不能直接解释为硬件不支持。`FAIL` 表示算子能运行，但没有通过本轮数值要求。为了诊断，FAIL 仍可测时间，但不能当成可启用的优化。

## 第四层：metrics/report，先正确，再讨论快慢

表里先看数值验收，再看最大绝对误差；完整 relative L2、余弦、失败元素数和逐输出误差在展开项及 JSON 中。零参考且误差非零时 relative L2 无定义，零范数的余弦也无定义，报告显示 null，而不是伪造正常数值。

随后看 Event 中位数、同步 Wall、Event P90 和增量峰值显存。两个时间差距很大时，要调查 CPU 提交、事件、同步等开销，不能仅凭表判断算力/带宽瓶颈。P90 是本轮微基准样本分位数，不是线上请求 P90。显存不包括其他进程和全部厂商库分配，不能用它承诺某张显卡一定能运行完整模型。

合成结果不能冒充真实模型结果；单算子通过也不能跳过完整 Block、完整去噪与生成质量验证。本轮不实现自动调优、不修改已有推理默认值。

## 本轮验证记录（H20，2026-11-13）

- 31 项安装包测试通过；包含 9 项新增的配置、均衡顺序、误差与报告检查。
- 合成 Attention、SwiGLU、QK Norm+RoPE 完成 GPU 运行；后两种按 exact 验收通过。
- 历史真实 QKV 形状 `[1,19304,56,128]` 下，Flash 的布局路径逐值一致。cuDNN 相对 Flash 最大绝对误差 0.0625、MAE 0.00016411764100515784、失败元素 158986/138371072（约 0.115%），没有通过预设 `atol=0.001, rtol=0.01` 的逐元素要求。以上计数与旧实验独立对照一致，没有为通过而放宽容差。
- 这个 FAIL 是相对于 Flash 的单算子诊断要求，不推翻此前对 cuDNN 完整生成效果的人工接受，也不改变已有推理默认值。融合路径相对于 cuDNN 参考的完整去噪一致性是另一项已有验证。
- 本轮时间仅对应单算子、特定输入、当前软件环境；没有新增完整生成加速比结论。测量前请确保同卡无其他计算任务；工具不强制占卡，也不锁定 GPU 时钟。

本地 Windows 的旧 Safetensors 不支持 `backend='pread'`，因此旧的完整卸载测试不适用于该环境；新增实验协议测试通过。完整依赖和 GPU 验证使用 H20 的既有固定环境，没有修改本地全局依赖。
